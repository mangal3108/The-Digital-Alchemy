Flow Image Brief

Real technology, photographed like a product catalogue: machined aluminium, fibre, silicon, patch panels, server rails. One distinct subject per page. Screens stay out of it — those come from screenshots of the running product.

51 prompts 1 subject per page 0 contain a screen or an interface

The world

Every prompt here is technology you could photograph on a bench: a server rail, a fibre termination, a silicon wafer, a machined billet with the swarf still on it. Shot with controlled studio light and shallow focus, the way a catalogue shoots a product — not the way stock shoots "technology."

That last distinction is the whole job. The default for this subject is glowing blue circuit boards, holographic overlays and matrix rain, and it looks cheap instantly. These prompts ban all of it by name and ask for real materials and real light instead.

Screens are deliberately absent. Generated interfaces are what produced "Eampany Value" in the old hero; real ones get captured from the site and admin panel and composited into the device frames already built in code.

Rules

  • Never caption this hardware as ours. We don't own a data centre or a machine shop. A generated photo of a server aisle is atmosphere and that's fine — the same way any company uses a photograph of a thing it doesn't own. It stops being fine the moment a caption says "our infrastructure." I'll keep the alt text and captions descriptive, never possessive.
  • No text, numbers or labels. Hardware is covered in tiny lettering and models render it as garbage. Every prompt bans it; leave the negative block in.
  • No screens showing anything. Displays should be off, dark, or absent. Anything on a screen gets composited from a real capture.
  • No people, hands or faces.
  • One accent, on one element. Each entry names a hex. Everything else stays in the material's own tone — raw aluminium, steel, black anodise, glass. That restraint is what stops forty tech photos turning into a single wash of colour.
  • Save with the exact path shown. The build resolves by folder and filename, then trims, resizes, converts to WebP and registers each one automatically.
